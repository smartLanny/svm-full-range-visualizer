# 0002 3D 统一坐标与单元格布局；俯视用正交相机并压平高度

- 状态：已采纳（2026-09）

## 背景
- 旧实现中曲面/热力图的横轴按 `log10(档位亮度+1)` 摆放，柱状图却按列序号等距摆放；开场动画从柱子渐变到热力图时每一列都横向跳动，这是“看着卡”的主要来源之一。
- 柱子固定深度 0.8（≈16 个灰阶），而低灰阶行间距只有 4–6 个灰阶，俯视时柱子互相压叠。
- 俯视用的是透视相机：高的柱子/尖峰朝镜头方向“倒”出来，盖住相邻格子和坐标轴；视角也没对正，热力图斜着显示。

## 决定
1. 所有 3D 呈现共用一套坐标：X = `log10(档位亮度 + 1)`，Z = 灰阶（线性），Y = SVM。
2. 引入**单元格**：每个测量点的单元格边界取相邻测量点坐标的中点（首尾向外延伸半个间距）。柱子 = 单元格按比例收缩后拉伸出的立方体；热力图色块与之严格对齐。
3. **俯视 = 正交相机 + 高度压平**。进入俯视时高度平滑降到 0，退出时平滑升回；相机坐标轴对正（灰阶向上、亮度向右），自动适配画幅留白。
4. 立体视角使用透视相机；立体 ↔ 俯视的切换是连续的镜头运动，末端无缝换成正交相机。
5. 标签避让：坐标刻度使用对数友好刻度（1, 2, 5, 10, 20, 50, 100, 200, 500）并按间距剔除；等高线数值标签带底色并在标签处断开线条；数值表按单元格大小自动决定是否显示，永不重叠。

## 后果
柱状图不再是等距排列，低亮度档位的柱子较窄；这是物理真实的，且与 2D 图、热力图一致。

## 补充（评审修复轮）
- **缺失/剔除单元格**：曲面按单元格精确覆盖——每个细分小块只属于一个单元格，只有该单元格有值才绘制；插值只在有值的角点间重新归一化，孤立的有效单元格也画满整个矩形。缺失单元格画成中性灰 45° 斜线“无有效数据”底面，色标旁出现对应图例；曲面在洞口边缘有侧墙，等高线在洞口处截止。悬停缺失单元格会显示原因（剔除原因与原始读数，或“未测量”）。
- **高度上限的斜线纹理**只画在朝上的面，侧墙和柱子侧面保持干净；拖动高度上限 / 色标上限时就地更新，不重建场景。
- **差值图色标范围**取 p95(|Δ|) 向上取整到 {0.5, 1, 1.5, 2, 3}，超出部分饱和（色标两端标 “≥ +R / ≤ −R”），最多 4 条等高线；个别离群点不再决定整张图的色标。发散色标中点为近白色 `#dfe1e5`（蓝-白-红）。没有任何有效差值的行/列不画。
- **竖屏画幅（9:16）**：~~灰阶轴加深 1.5 倍~~（已取消，见“稳定的热力图比例”），标题、图、色标整组垂直居中。
- **正视 / 侧视**自动纵向放大（×1.5…×8），让剖面占绘图区约一半高度；数值轴仍是真实 SVM，副标题注明“纵向放大 ×N”。
- **缩放 / 平移后**俯视画面裁剪在安全区内，坐标轴变成钉在边缘的标尺；透视视角只避开标题带和色标。

## 补充（第二轮修复）
- **并排对比 = 每个面板一个子视口**：两条记录各画在自己的单元格里，各用一台相机（同一朝向、同一比例：B 的相机就是 A 的相机平移到 B 的面板，再用 view offset 放到 B 的单元格），因此无论高度上限、高度倍率还是旋转角度，两个面板在屏幕上都不会互相遮挡。每个面板有自己的亮度/灰阶/数值轴；缩放、平移、旋转对两个面板同步生效，内容裁剪在各自的单元格内；悬停只拾取指针所在单元格的面板。
- **横屏并排、竖屏上下**：画幅宽高比 ≥ 1 时 A 左 B 右；< 1（如 9:16 导出/演示）时 A 在上、B 在下，每格有自己的标题行和坐标轴带，1080×1920 导出里两块图约占画面高度的 90%。竖屏视角按单元格的形状决定（窄单元格与竖屏单图同样处理）；~~灰阶轴加深~~已取消，两条的排列也改为按底板大小选（见“稳定的热力图比例”）。
- **面板标题永不隐藏**：标题（“A · 设备 · 模式”）居中在各自面板的地形包围盒上方，限制在本单元格内、不压色标和主标题；放不下时先换成两行（设备 / 模式），再缩短设备名，模式始终可见（两个模式开头相同时保留末尾，如“…Pro 关 / …Pro 开”）。两个面板的标题行数一致。
- **单图标题**：竖屏（色标在下方）时标题使用整个宽度；放不下时先分两行（设备 / 模式），副标题在“ · ”处换行，最后才用省略号。演示模式下标题从 `presentSafeLeft` 开始，避开左上角的退出按钮（导出不受影响）。
- **等高线标签在 3D 中互不重叠**：标签在底板平面上已互相错开，但不同高度的标签投影后可能重叠；每帧按屏幕矩形做软碰撞（长线的标签优先，靠近时连续淡出）。被地形挡住一部分的标签直接淡出，不再半隐半现。
- **数值表整体决定**：不再逐格决定。统一字号取每个面板 80% 格子都放得下的最大字号（≤ 12.5 px）；若连最小字号 7 px 都只能放下某个面板不到 60% 的格子，则所有面板都不显示数值，并在视图左下角提示“格子太小”（并排对比两面板同一决定）。等高线此时不再被数值切断，等高线标签照常显示。

## 补充（稳定的热力图比例）
- **背景**：用户反馈“热力图之类的不应该跟着实际比例变化，比例不能变太细太窄”。此前底板的灰阶轴随画幅拉伸：竖屏 ×1.5，3–6 条网格按单元格最多 ×2——1600×900 分析模式 6 条（3×2）时每块热力图宽 : 深约 0.68，1280×720 分析模式两条并排约 0.8，9:16 演示 4 条约 0.6；底板本身的宽深比还随记录的亮度范围、亮度上限和低灰阶裁剪变化（内置记录：默认 500 nits 上限 + 裁剪时 1.19–1.36，显示全部亮度时 1.26–1.47；亮度范围窄的导入记录会更窄）。
- **决定**：
  1. **所有热力图同一比例**：宽 : 深 = `PLATE_ASPECT` = **1.4**（`scene3d/engine/plate.ts`），适用于 3D 底板（俯视热力图、曲面、柱状、数值表；单个、并排 2–6 条、差值图；立体 / 俯视 / 正视 / 侧视；开场动画；所有导出）和统计卡片缩略图。灰阶轴的缩放只由数据范围算出（`plateDepthScale`：对数亮度跨度 × SX ÷ (1.4 × 灰阶跨度 × SZ)），与画幅、单元格、网格无关；画幅多出的空间用于居中和留白（单元格内居中，竖屏整组垂直居中），不再拉伸。模型因此不依赖画幅，改变窗口只在并排网格变化时重建。
  2. **取常数而不是区间**：同一组数据在单图、并排、差值图、导出、统计卡片里形状完全一致，换亮度上限、开关低灰阶裁剪也不变形。取值比较了 1.25 / 1.4 / 1.55 的截图：1.25 在 16:9 画幅里更窄、横向留白更多；1.55 在网格里更扁（1600×900 分析模式 6 条因此改排 2×3）；1.4 介于 4:3 与 3:2 之间，接近原来横屏默认（1.19–1.45），横屏单图与原来几乎一样。
  3. **并排**：各面板共用一个亮度 / 灰阶域，这个域的底板是 1.4；范围比域小的记录只覆盖自己那一部分（共用坐标轴，便于对比），所以单个面板的热力图在 1.0–1.5 之间（内置记录实测）。色标仍全体共用。
  4. **网格按底板大小选**：`gridFor` 对所有候选网格（两条也一样）计算单元格里 1.4 的底板最大能有多大，取最大者；16:9 / 9:16 的习惯网格（`defaultGrid`）有 1.4 倍面积（约宽 18 %）的偏好，只有明显更好的网格才替换它（常见画幅里习惯网格与最佳网格差 ≤ 1.3 倍，明显更好的 ≥ 1.6 倍）。结果：16:9 与 9:16 保持原有排列（2 条左右 / 上下，3 条一行 / 一列，4 条 2×2，5–6 条 3×2 / 2×3）；方形画幅（1:1 导出）2 条上下、3 条 2×2、5–6 条 2×3；1600×900 分析模式 3 条 2×2；1280×720 分析模式 5–6 条 2×3。
  5. **统计卡片缩略图**不再固定 128 px 高：高度 = 宽 ÷ 1.4（`stats/heatmap.ts` 的 `thumbHeight`，屏幕与导出共用），310 px 宽的卡片里热力图约 250 × 179（原来 251 × 128，宽深比 1.96）。卡片因此高约 50 px；导出的卡片网格照常按画幅选择（卡片高度随宽度增加，`chooseCardGrid` 不依赖单调性）。
- **被取代**：上文“竖屏画幅：灰阶轴加深 1.5 倍”“灰阶轴加深按单元格的形状决定”“底板加深（1–2 倍）”，以及“2 条保持原样（横屏左右、竖屏上下）”的固定规则（两条也按底板大小选，16:9 / 9:16 下结果不变）。竖屏整组垂直居中、竖屏网格为色标预留 80 px、窄单元格的立体视角调整保留。
- **测试**：`plate.test.ts`（每条内置记录 × 裁剪开关 × 亮度上限 500 / 200 / 100 / 50 / 全部（窄范围代替窄的导入记录）；并排 2–6 条；差值图——底板比例恒为 1.4，面板在 1.0–1.5 之间）、`cells.test.ts`（1–6 条 × 16:9 / 9:16 / 1:1 导出、1600×900 与 1280×720 分析模式、演示舞台：底板保持比例、不小于最大候选底板 ÷ 偏好、所选网格）、`stats/heatmap.test.ts` 与 `stats/export.test.ts`（缩略图高度、卡片高度）。
