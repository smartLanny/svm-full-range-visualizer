# 0009 统计摘要指标定义

- 状态：已采纳（2026-09；2026-09 细化；2026-09 加入覆盖率与评比规则、典型亮度 SVM 与 2D 曲线对齐，实现见 `src/data/stats.ts`，单元测试见 `src/data/stats.test.ts`；2026-09 补充场景加权参考，见文末）

## 统计范围

当前低灰阶裁剪设置（默认隐藏 G < 15）下、档位亮度 ≤ 上限（默认 500 nits）的有效测量点，即
`gridView(record, { clipLowGray, maxNits })`。缺失值（`null` 或非有限 SVM）一律排除，**绝不当作 0**。
页面顶部的“统计范围”一行始终写明当前裁剪、亮度上限和灰阶截面，切换设置后所有指标即时重算。

## 面积加权

每个测量点占据一个**单元格**（与 3D 柱状图 / 热力图同一套，见 0002）：横向边界取相邻测量点
`x = log10(档位亮度 + 1)` 的中点（首尾外延半个间距，下限 0），纵向边界取相邻灰阶的中点（夹在 0–255）。
单元格面积 = Δx × Δ灰阶。这样低亮度档位、稀疏的高灰阶行不会因为“测得多”而被过度计数，统计结果与
热力图上肉眼看到的面积一致。

## 指标

| 指标 | 定义 |
| --- | --- |
| 安全占比 | SVM < 0.4 的单元格面积 ÷ 有效单元格总面积 |
| 中等占比 | 0.4 ≤ SVM < 1.0 的面积占比（= 1 − 安全 − 临界） |
| 临界占比 | SVM ≥ 1.0 的面积占比（恰好 0.4 计入中等，恰好 1.0 计入临界） |
| 平均 | 面积加权平均 SVM |
| 峰值 | 统计范围内最大 SVM，附其（灰阶, 档位亮度, 实测亮度）；并列取第一个 |
| 全白达标亮度 | 统计范围内最高灰阶行（通常 G255）上，按实测亮度排序，从最亮的测量点向下连续满足 SVM < 0.4 的最低实测亮度，即“从此亮度起（向高亮度方向）持续达标”。最亮点本身不达标则为“—”（始终未达标）；全部达标时标注“全程达标”。取测量值，不做插值。受亮度上限影响（上限以上的档位不参与） |
| 典型亮度 SVM | 当前灰阶截面（`sliceGray`，不受裁剪 / 上限影响）在 2 / 10 / 50 / 100 nits 实测亮度处的 SVM，**直接读 2D 图画出的那条曲线**：灰阶截面取 `smoothSliceAtGray`（在测量行上与原始值完全相同，行间沿灰阶做单调三次插值），再在 log10(nits) 上用单调三次样条（Fritsch–Carlson，不越过相邻测量值）取值，与 2D 数据表 / 悬停读数逐位一致（见下文“与 2D 读数一致”）；超出该截面测量范围为“—” |
| 有效单元格 | 统计范围内非缺失的测量点数量 |
| 覆盖率 | 有效单元格面积 ÷ 统计范围的名义面积。两者都在**名义单元格布局**上计算：统计范围内矩阵的全部行（灰阶）和列（档位亮度），包括整行 / 整列都没有有效值、被 `gridView` 省略的行列。缺失或按 0012 剔除的格计入名义面积、不计入有效面积 |
| 已剔除（范围内） | `dataset.excluded` 中灰阶与亮度百分比都落在统计范围内的剔除点数量（TSV 导出） |

### 与 2D 读数一致

早期实现用 `grid.sliceAtGray`（行间线性、log10(nits) 上线性）求典型亮度 SVM，而 2D 图用平滑截面 + 单调样条，
两者在测量点之间相差到小数第二位（如 iPhone 17 Pro Max 标准 G127：2 nits 处 2.29 vs 2.272）。评测时交叉核对
数字会看到不一致，因此统计改为调用同一组函数（`sliceSvmAt` → `smoothSliceAtGray` + `buildSpline` / `evalSpline`），
单元测试 `svmAt equals the 2D chart data table` 用 2D 的 `buildScene` + `buildTable` 在测量行和非测量行（如 G100.5）
上逐值比对。两种插值在**测量点上**完全相同，只在测量点之间不同；单调样条不会越过相邻测量值，所以不会凭空制造
更好或更差的读数。线性规则 `interpolateAtNits` 仍保留为参考实现。

### 覆盖率与“最佳”评比

剔除异常点（0012）后，一条记录的统计只基于较小的有效范围——被剔除的多是低亮度噪声区、往往也是 SVM 高的区域，
直接比较会让它“更好看”。因此：

- 每行 / 每张卡片显示覆盖率（`有效 239 / 323 格` 附在下方或悬停提示中）；有剔除点的记录带“已剔除 N”徽标，
  悬停列出按原因的数量、范围内数量与说明。
- 覆盖率低于**可见记录覆盖率中位数的 90%** 的记录不参与“最佳”评比：各列最佳值只在可比记录中选出；
  低覆盖率记录的值即使不差于该最佳值也不高亮，而是显示 ⚠ 标记和提示；表格和卡片下方有脚注说明规则。

统计范围内没有任何有效测量点时（例如裁剪 + 上限去掉了全部行列），所有占比、平均、峰值为“—”，卡片显示提示而不是 0。

## 补充：场景加权参考（Scenario-weighted reference，2026-09）

实现见 `src/data/scenarios.ts`（纯函数，按“记录矩阵 + 场景配置”缓存），单元测试见 `src/data/scenarios.test.ts`。

### 决定

在上面的面积占比之外，统计页给每条记录一个**参考值**“场景加权 SVM”：把（档位亮度, 灰阶）平面上三个典型使用场景的
平均 SVM 按使用权重合成一个数，用来回答“日常使用中大概会不会看到频闪”。它是**参考**，不替代安全 / 中等 / 临界占比、
平均、峰值等指标，这些定义一律不变。

| 场景 | English | 档位亮度（G255 nits） | 灰阶 | 默认权重 |
| --- | --- | --- | --- | --- |
| 夜间 | Night | 2 – 20 | G15 – G100 | 30 % |
| 室内 | Indoor | 50 – 250 | G15 – G255 | 50 % |
| 户外 | Outdoor | 400 – 500 | G128 – G255 | 20 % |

- **亮度轴统一以 500 nits 为上限**（用户决定）：户外是 400 – 500 nits，不是“400 以上”；各场景的上限也不能设到 500 以上。
  最亮档位不到 400 nits 的机型在户外场景里就是没有数据（见下文“不外推”）。
- **权重**：夜间单位亮度下最敏感（暗环境、瞳孔放大、低亮度档位的 PWM / 低频调光最明显），所以权重高于它在使用时长里的
  占比；但大部分时间在室内，室内权重最大；户外亮度高、频闪通常最弱，权重最小。权重在设置中可改，计算时按比例归一化。

### 定义

- **每个场景的值** = 场景矩形内单元格 SVM 的**面积加权算术平均**。面积在 **log10(档位亮度) × 灰阶** 平面上计算（亮度感知
  近似对数；热力图和面积占比的横轴是 log10(nits + 1)，高亮度处与之几乎相同，但在几 nits 处会压窄，这里不压，夜间场景里最暗的
  档位不被低估）。跨越矩形边界的格只按与矩形重叠的部分计面积。缺失、非有限、降噪判为“无有效数据”的格
  **不计入**（绝不当作 0），同时报告有效数据覆盖场景矩形面积的比例（覆盖率）。
- **单元格布局**：记录矩阵的**名义布局**（所有有限灰阶行、所有正档位亮度列，含整行 / 整列无有效值的），内部边界取相邻测量点
  的中点（与统计、热力图同一个 `cellEdges`），横向用 log10(nits)。**不外推**：最外侧的边界停在最低 / 最高的实测行和列上，
  而不是像热力图那样向外延伸半个间距——否则最亮 380 nits 的机型会拿 380 nits 那一列去“覆盖”户外场景。
- **数据**：与统计页其余指标相同，用降噪后的显示记录（`processedOf` / `displayOf`，关闭降噪即原始读数）。
- **与视图无关**：场景有自己的亮度和灰阶范围（灰阶从 G15 起），不受统计范围的低灰阶裁剪和亮度上限影响，
  切换这些设置参考值不变。
- **算术平均而不是几何平均**：几何平均会被远低于阈值的小值拉低（0.05 与 0.1 在对数上相差和 1 与 2 一样大），
  过度放大“看不见的差异”，并让一小块 SVM≈0 的区域压低整个场景；算术平均按面积反映“这个场景里平均能看到多少频闪”。
- **综合** = 各场景均值按权重加权平均。场景没有数据，或有效覆盖率**低于 40 %** 时不计入，其余场景的权重按比例重新分配，
  界面标注“缺户外数据，权重已重新分配”（⚠）。没有任何场景可用时综合为“—”。
  取 40 % 而不是恰好 50 %：小米 18 Pro Max（自适应刷新 Pro 关）第一次测量（黑场噪声大，现保存在
  `test-fixtures/xiaomi18promax_v1_off.json`）降噪后把黑场附近的读数显示为无有效数据，夜间场景的覆盖率恰为 49.98 %；
  50 % 的门槛正好落在一条真实记录上，会丢掉它很差的夜间（5.19），让综合从 2.14 变成看起来“全场最好”的 0.83。
  噪声大的测量正是覆盖率偏低的时候，门槛不能让它因此显得更好。40 % 以下时均值只描述场景的一小部分，不再有代表性。
  （重测后的内置小米 18 Pro Max 三个场景都是 100 % 覆盖：关 1.66，开 1.13。）
- **分级**（综合与各场景相同）：< 0.4 **无感**，0.4 – 1.0 **轻微**，1.0 – 3.0 **可见**，≥ 3.0 **强烈**；恰好落在边界上的值
  归入较高一级。0.4 / 1.0 与全应用的安全 / 临界阈值（`SVM_SAFE` / `SVM_CRITICAL`）一致；3.0 是显示用的分界（等高线也画 3.0），
  不是标准阈值。颜色沿用安全 / 中等 / 临界的绿 / 橙 / 红，强烈用洋红 #d946ef（tailwind `strong`）。

### 展示

- **卡片**：底部一块紧凑的“场景参考 [参考]”：右侧是综合值（等级色点 + 数值 + 等级），下一行三个场景（名称 + 按等级着色的
  均值 + 等级词；等级词放不下时整个省略，不截断）；缺数据的场景显示“缺数据”，权重被重新分配时综合前有 ⚠。整块的悬停提示
  写明本记录各场景的值、覆盖率、实际权重，以及全部假设（范围、权重、对数面积、算术平均、降噪数据、只是参考）。统计范围内
  没有有效点的卡片也显示这一块（参考值与统计范围无关）。
- **表格**：覆盖率之后的“场景参考（参考值）”列组：综合 / 夜间 / 室内 / 户外（副标题为归一化权重），可排序（越低越好，
  缺失永远排最后），“复制为 TSV”在末尾追加这四列。评比规则单独定：场景参考不受统计范围覆盖率规则约束；**权重被重新分配的
  综合值不参与“最佳”评比**（与其他记录的综合不是同一组场景），值不差于最佳时显示 ⚠；计入综合的场景列照常评比。
- **导出**：统计卡片与统计表格的导出画同样的块和列（竖屏分两段时场景列在第二段），表格图例条加一句说明。
- **设置**：设置面板中可折叠的“场景参考（统计）”：每个场景的亮度范围（≤ 500 nits）、灰阶范围和权重，以及“恢复默认”。
  保存在本地设置 `scenarios` 中（新键，旧存档自动用默认值，不需要提升 `SETTINGS_REV`）；加载时逐个场景校验
  （min < max、nits > 0 且 ≤ 500、灰阶 0–255、权重 0–100），不合法的场景回退到它的默认值，权重全为 0 时回退到默认权重。
- **3D 俯视叠加层**（默认关，参数面板“叠加层 → 场景范围”）：在俯视热力图上用虚线框出三个场景矩形（深色描边 + 浅色虚线，
  与深色实线的等高线区分），左上角标“夜间 30%”；框按底板裁剪，超出当前亮度上限的场景不画。只在地形压平、相机朝下时淡入，
  开场动画中不显示。
